# Security boundaries and reporting

This is a single-user educational reference. It has no remote authentication, tenant isolation, automatic retention service or arbitrary command executor. Local filesystem permissions govern its files. Loopback-only client destinations do not sandbox the model server. Native decoders and package installation remain separate trust boundaries; documented container restrictions reduce access without proving immunity to parser vulnerabilities.

Use fictional fixtures before private inputs. Reports, OCR, retained images, model replies, database history and backups may disclose source material. Removing one original does not erase its derivatives. Review proposals against visible evidence; schema checks and hashes do not establish factual truth or authenticate an unknown sender. Inventory confirmations are local workflow controls, not authentication against a user who controls the machine.

For a non-sensitive bug, open a GitHub issue with a minimal synthetic reproduction, code version, expected/actual behavior and dependency versions. Do not attach credentials, private documents, model weights, host paths or personal screenshots. For a security issue that would expose private data, use GitHub's private vulnerability reporting if it is enabled. Otherwise request a private contact channel in an issue without publishing exploit details or sensitive evidence. No response-time or support guarantee is offered.

Keep dependencies and runtimes under review. Reproduce the relevant tests before upgrading; preserve original failed attempts and use new output directories. This policy does not claim that every advisory or deployment configuration has been audited.
